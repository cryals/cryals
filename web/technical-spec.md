# ТЗ: персональная страница AL-S

> Актуализация: дальнейшие требования имеют приоритет над первоначальными разделами ниже. Входной экран содержит часы и вращающийся цветной логотип STOPCO; нажатие открывает визитку и запускает трек. Плеер использует обложку как кнопку, ссылку в названии и вертикальную громкость справа с начальным положением 20% и квадратичной шкалой. GitHub показывает календарь вкладов и компактную полоску языков без списка репозиториев и счётчиков. Квадратный магнитный курсор включается для мыши и отключается при reduced motion или touch; hover применяется к интерактивным элементам. Дизайн может отходить от исходной терминальной схемы по прямому указанию AL-S.

Статус: утверждённая спецификация первой версии.

## 1. Цель

Создать одностраничную личную страницу-визитку AL-S на Node.js + Vite. Страница должна быстро сообщать, кто такой AL-S, как с ним связаться, какие у него GitHub-активность и языки, где он находится, а также давать компактный музыкальный плеер.

Визуальная реализация обязана следовать [design.md](design.md). Референсы из пользовательских вложений используются как источник идей по композиции: полноэкранный фон, центральная карточка, полупрозрачные панели, плеер и мягкие эффекты указателя. Они не заменяют правила `design.md`.

## 2. Ограничения репозитория

- Код сайта, ассеты и конфигурация сайта находятся только в `web/`.
- За пределами `web/` допускаются только изменения CI/CD и `agents.md`.
- Не добавлять секреты GitHub API, токены или приватные данные в клиентский bundle.
- Не копировать референсные изображения в репозиторий без явного разрешения; использовать существующие ассеты пользователя.

## 3. Стек и структура

Рекомендуемый стек: Vite + React + TypeScript, запускаемый Node.js. Сборка должна работать командами `npm run dev`, `npm run build` и `npm run preview`.

Предлагаемая структура:

```text
web/
  public/
    image/
      avatar/
      background/
    logo/
    music/
  src/
    components/

```

Названия файлов можно адаптировать под фактический шаблон Vite, сохраняя разделение компонентов и данных.

## 4. Данные профиля

Вся изменяемая информация хранится в одном типизированном объекте, а не размазывается по JSX:

```ts
export const profile = {
  displayName: 'AL-S',
  discord: { label: '@alssss', href: 'https://discord.com/users/616677573761433630' },
  telegram: { label: '@cryalsss', href: 'https://t.me/cryalsss' },
  steam: [
    { label: 'Al', href: 'https://steamcommunity.com/id/cryalsss/' },
    { label: 'A L - S', href: 'https://steamcommunity.com/id/cryals' },
  ],
  email: 'als@stopco.ru',
  website: { label: 'stopco.ru', href: 'https://stopco.ru' },
} as const;
```

В интерфейсе показывать имя сервиса, пользовательский идентификатор и понятный hover/focus state. Ссылки открываются в новой вкладке с `rel="noreferrer noopener"`; `mailto:` остаётся в текущем контексте.

## 5. Медиа и случайный выбор

Источники:

- аватары: `public/image/avatar/`;
- фоны: `public/image/background/`;
- музыкальные файлы и метаданные: `public/music/`;
- логотипы сервисов: `public/logo/`.

Текущие файлы, которые должны поддерживаться:

- `public/image/avatar/avatar.png`;
- `public/image/background/background.gif`;
- `public/music/Карабас и Несуразности - Изобретатель.mp3`;
- `public/music/music.txt`;
- `public/logo/discord.svg`;
- `public/logo/steam.svg`;
- `public/logo/stopco.png`;
- `public/logo/telegram.svg`.

Так как браузер не предоставляет надёжный список файлов из `public/`, список ассетов задаётся в `src/data/media.ts` или генерируется на этапе сборки. На каждую полную загрузку документа выбирается один случайный avatar и один случайный background. Для стабильности в рамках текущей вкладки выбор не меняется при React re-render. При наличии только одного файла используется он.

Алгоритм:

1. импортировать массивы доступных URL;
2. выбрать индекс через `crypto.getRandomValues`, с fallback на `Math.random`;
3. сохранить выбор в состоянии `App`, но не в `localStorage`, чтобы перезагрузка действительно могла сменить медиа;
4. если файл не загрузился, перейти к первому доступному файлу и показать страницу без блокировки интерфейса.

Фон должен заполнять viewport через `cover`, сохранять центр композиции, иметь затемняющий слой и не мешать читаемости карточки. GIF не должен запускать отдельную тяжёлую обработку кадров.

## 6. Компоновка страницы

Страница состоит из одного viewport-first экрана с вертикальным overflow на мобильных устройствах.

1. Фоновый слой: выбранное изображение, затемнение и лёгкое размытие только при допустимой производительности.
2. Верхняя системная зона: маленькая кнопка mute/unmute и необязательный terminal status.
3. Центральная карточка: avatar, `AL-S`, короткое описание/статус, geo badge и social links.
4. Музыкальный плеер.
5. GitHub-активность и языки.
6. Нижняя строка: сайт, email и технический статус загрузки.

На desktop карточка центрируется с максимальной шириной около `560px`; внутренние блоки используют одноколоночную структуру. На ширине до `600px` карточка занимает почти всю ширину, не создавая горизонтального скролла. Минимальная область нажатия интерактивных элементов — `42px`.

## 7. Профиль и ссылки

Карточка профиля должна содержать:

- круглый аватар с тонкой светлой границей;
- крупный заголовок `AL-S`;
- короткую строку статуса в terminal-стиле, например `> PERSONAL NODE / ONLINE`;
- гео-индикатор с текстом `Russia, Vladimir` или данными геосервиса;
- отдельные link buttons для Discord, Telegram, Steam #1, Steam #2, Email и сайта.

Для Discord и Telegram использовать предоставленные SVG. Для Steam использовать `steam.svg`. Если нужен общий значок сайта, использовать `stopco.png` только как брендовый asset, не как декоративную иконку.

## 8. Геолокация

Геолокация нужна как декоративная информация карточки, а не как трекинг пользователя.

- не запрашивать разрешение на GPS через `navigator.geolocation`;
- не определять и не сохранять точное местоположение посетителя;
- сначала показывать безопасный fallback `Russia, Vladimir`;
- если позже подключается внешний IP-geolocation endpoint, запрос выполнять только сервером/edge-функцией, не хранить IP и явно обрабатывать отказ/лимиты;
- в первой версии достаточно статического значения из `profile.ts`.

## 9. Музыкальный плеер

### Источник и старт

Плеер использует MP3 из `public/music/`. `music.txt` читается как источник названия/исполнителя, если его формат поддерживает парсинг; при нераспознанном формате применяются значения `Изобретатель` и `Карабас и Несуразности` из имени файла.

При первом пользовательском действии (клик по Play, карточке или mute) плеер создаёт/активирует `HTMLAudioElement` и устанавливает `volume = 0.2`. Автовоспроизведение со звуком не обещается: браузер может заблокировать его до жеста пользователя. Если autoplay разрешён, трек может начать играть после загрузки с громкостью `20%`.

### Управление

Обязательные элементы:

- Play/Pause;
- progress range с текущим временем и общей длительностью;
- mute/unmute;
- volume range, начинающийся с `20%` при первом запуске;
- название трека и исполнитель;
- доступное состояние загрузки/ошибки.

При окончании трека кнопка возвращается в Play и прогресс сбрасывается. Ошибка audio не ломает страницу: показывается компактное сообщение `AUDIO UNAVAILABLE`, остальные блоки работают.

Иконки плеера — Google Material Symbols/Icons в solid-варианте без декоративного округления. Для социальных сетей — Simple Icons или предоставленные SVG. Каждая иконка должна иметь `aria-label` или видимый текст.

## 10. GitHub-статистика

### Содержимое

Блок показывает профиль AL-S и включает:

- avatar/логин GitHub, если доступен;
- количество публичных репозиториев;
- число followers;
- total contributions за выбранный год;
- contribution heatmap или компактную сетку активности;
- список 4–6 последних/избранных репозиториев;
- язык каждого репозитория;
- итоговое распределение языков по объёму кода.

### Источник данных

В первой версии использовать GitHub REST API для публичных данных и собственный слой `lib/github.ts`. GitHub GraphQL для contribution calendar подключать только через server-side endpoint с токеном, если REST-данных недостаточно.

Токен хранится только в server/edge environment variable. Если серверного endpoint ещё нет, клиент показывает публичные REST-данные и вместо приватной contribution-сетки — понятный fallback без раскрытия токена.

### Состояния

- loading: терминальные skeleton-строки без мигающих тяжёлых анимаций;
- success: данные и время последнего обновления;
- rate limit: `GITHUB RATE LIMITED`, сохранение предыдущих данных при наличии;
- network error: `GITHUB OFFLINE`, без скрытия профиля и социальных ссылок;
- empty: аккуратное сообщение без выдумывания статистики.

Языки считать по байтам, полученным из API репозиториев, затем нормализовать в проценты. Сумма отображаемых процентов должна быть `100%` с поправкой округления. Не подменять реальные значения визуально сгенерированными цифрами.

## 11. Cursor-эффекты и motion

Эффекты должны усиливать ощущение интерфейса, но не превращать страницу в демонстрацию анимаций.

- мягкое свечение следует за указателем через CSS custom properties;
- короткий trail из ограниченного числа точек исчезает через opacity;
- hover карточек даёт малый сдвиг/изменение границы;
- не использовать бесконечные тяжёлые canvas-эффекты;
- ограничить число частиц/trail nodes и удалять невидимые элементы;
- при `prefers-reduced-motion: reduce` отключать trail, parallax и постоянные анимации;
- на touch-устройствах cursor-слой не создаётся;
- pointer-эффекты не должны перехватывать клики (`pointer-events: none`).

## 12. Дизайн и доступность

- использовать токены и типографику `design.md`;
- сохранять контраст текста на фоне карточки и overlay;
- обеспечить видимый `:focus-visible`;
- не кодировать смысл только цветом;
- социальные кнопки имеют текст/tooltip и доступное имя;
- прогресс и громкость — нативные или корректно размеченные range-контролы;
- на мобильных пользователь должен получить доступ к каждому блоку без hover;
- `alt` аватара: `AL-S avatar`; фон декоративный и имеет пустой `alt`;
- документ имеет один `h1`, логические `section` и корректный tab order.

## 13. Производительность и безопасность

- не загружать все варианты фоновых изображений одновременно: выбрать URL до рендера активного слоя;
- задать `loading="lazy"` для вторичных изображений, но не для первого avatar;
- сжимать только новые ассеты, не перезаписывая пользовательские файлы без разрешения;
- кэшировать GitHub-ответ на короткое время на сервере/edge, чтобы не упираться в rate limit;
- экранировать текст API перед выводом как текст, не вставлять HTML из внешних данных;
- внешние ссылки открывать с `noopener noreferrer`;
- не собирать аналитику, cookies или точную геолокацию без отдельного согласия.

## 14. Критерии готовности

Считается готовым, если:

- `npm run build` завершается без ошибок;
- страница отображается на desktop и мобильной ширине без горизонтального скролла;
- при нескольких avatar/background после полной перезагрузки возможен новый случайный выбор;
- текущие файлы из `public/image`, `public/music` и `public/logo` используются без ручного копирования;
- плеер стартует с громкостью `0.2` после разрешённого пользовательского действия;
- Play/Pause, seek, mute, volume и ошибка загрузки работают независимо друг от друга;
- все указанные ссылки ведут на правильные адреса;
- GitHub loading/success/rate-limit/offline состояния обработаны;
- языковая статистика рассчитывается из полученных данных и не содержит выдуманных значений;
- эффекты курсора отключаются для touch и reduced-motion;
- keyboard navigation и focus-visible проверены вручную;
- в `git status` отсутствуют изменения за пределами `web/`, CI/CD и `agents.md`.
